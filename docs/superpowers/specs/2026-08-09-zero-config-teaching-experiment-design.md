# 零配置人工提取与 AI 辅助提取教学实验设计

日期：2026-08-09
状态：已获用户确认

## 1. 目标

在现有“教学实验”模块中提供一套开箱即用的交叉实验，用 30 名学生比较两种文献数据提取方式：

1. 纯人工提取：学生阅读论文并自行填写全部字段；
2. AI 辅助提取：系统展示 AI 预提取结果，学生核对后保留或修改。

系统必须自动完成实验初始化、学生分组、两轮任务编排、有效计时、自动评分和结果汇总。教师不需要创建项目、添加论文、分组或逐项评分；实际操作仅为发送学生入口并查看结果。

主要评价问题是：AI 辅助是否使学生提取得更快、更准确。次要问题包括覆盖率、证据质量、AI 建议采纳情况，以及学生纠正 AI 错误的能力。

## 2. 非目标

- 不建设通用的多课程实验编排平台；本阶段只支持一套版本化的默认实验。
- 不让教师在界面中编辑评分规则或实验统计模型。
- 不用大模型实时判断学生答案；评分必须可复现、可审计。
- 不将 AI 模式与纯人工模式分配给不同学生后直接进行非配对比较。
- 不删除现有教学项目、提交或人工复核记录。

## 3. 实验设计

### 3.1 平衡交叉设计

两篇难度相近的论文记为论文 A 和论文 B。学生加入时被自动分配到两条序列之一：

| 序列 | 第一轮 | 第二轮 |
| --- | --- | --- |
| M→AI | 论文 A，纯人工 | 论文 B，AI 辅助 |
| AI→M | 论文 A，AI 辅助 | 论文 B，纯人工 |

系统在同一写事务中比较两条序列的现有人数，并把新学生分配给人数较少的一条；人数相同时优先分配 `M→AI`，下一名因人数不等自然进入 `AI→M`。30 名学生正常加入时形成 15/15 分组，任何时刻两组人数差不超过 1。

同一篇论文在同一轮被两种模式处理，因此论文难度和轮次影响不会只落在某一种模式上。每名学生都完成两种模式，主分析采用个人内配对差值。

### 3.2 身份与重复进入

学生入口只要求“学号或姓名缩写”。系统使用默认实验 ID 与规范化后的学生标识查找参与者：

- 首次进入：分配固定序列并一次性创建两轮提交；
- 再次进入：恢复原序列、当前轮次、草稿和计时状态；
- 已完成：进入完成页，不创建新记录。

默认实验内学生标识必须唯一。系统不在学生界面显示统计分组代码，避免学生自行换组。

### 3.3 论文和标准答案

仓库包含版本化配置 `config/teaching/default-experiment.v1.json`，其中固定保存：

- 实验 ID、显示名称和配置版本；
- 论文 A/B 的标题、DOI、可访问来源链接；
- 六个字段的 AI 初始提取值、页码和证据；
- 六个字段的标准答案、允许别名、单位、数值容差、合法页码范围和证据关键词组；
- 评分规则版本。

配置本身足以运行实验，不依赖教师后台选择论文，也不要求运行时 `tribology.db` 中恰好存在对应记录。论文来源使用可访问链接，不把受版权限制的 PDF 提交到仓库。

默认配置是不可变的实验快照。一旦已有学生加入，修改内容必须发布为新的配置版本和实验 ID，防止同一实验内学生使用不同题目或评分标准。

### 3.4 论文配对准入条件

默认配置发布前，两篇论文必须同时满足：公开可访问；六个字段均有可复核答案；篇幅、信息分散程度和表格/图形复杂度相近；不存在一篇答案全部集中在摘要、另一篇需要全文搜索的明显失衡。两名独立复核者在发布配置前确认标准答案、允许别名、页码和证据规则。

AI 快照必须由同一模型版本、同一提示和同一提取流程生成，并原样冻结，不根据已知标准答案人工润色。论文选择只依据题目完整性与难度匹配，不依据 AI 恰好答对或答错多少；若 AI 在两篇论文上没有错误字段，错误纠正率和错误采纳率按定义显示“—”。

## 4. 操作流程

### 4.1 自动初始化

访问教学入口、学生 API 或教师看板时调用幂等的 `ensureDefaultTeachingExperiment()`：

1. 读取并验证版本化配置；
2. 检查论文、AI 答案和标准答案六个字段是否完整；
3. 使用稳定 ID 创建默认项目和两篇论文；
4. 已存在且配置校验和一致时不做写入；
5. 已有参与者但配置校验和不一致时拒绝覆盖并记录明确错误；
6. 无参与者时允许修复尚未开始的同版本初始化记录。

初始化失败时，学生入口显示“实验暂不可用”，不会创建半成品参与者；教师看板显示可诊断的配置错误。

### 4.2 学生端

学生从固定 `/teaching` 入口进入：

1. 输入学号或姓名缩写；
2. 系统自动恢复或创建实验身份；
3. 页面显示“第 1/2 轮”或“第 2/2 轮”、论文信息、当前模式和有效用时；
4. 完成当前轮并提交；
5. 第一轮提交后直接进入第二轮；
6. 第二轮提交后显示实验完成页。

纯人工模式中的值、页码和证据输入初始为空。学生 API 响应不得包含 AI 快照、标准答案、别名或评分规则。

AI 辅助模式预填 AI 的值、页码和证据。学生可以直接保留或编辑；提交前只需一次确认“已核对全部字段”，不要求逐字段点击采用按钮。系统通过 AI 初始快照与最终答案的规范化差异判断“未修改/已修改”，并保留字段级编辑事件用于审计。

六个字段的值为提交必填项。页码和证据保持可填写且强提示；缺失时允许提交，但会降低证据覆盖率，避免因引用格式问题阻断整轮实验。

### 4.3 教师端

现有教师认证继续保护 `/teaching/admin`，但实验配置不再依赖教师操作。教师看板默认打开当前版本的默认实验并自动刷新，提供：

- 完成人数与有效配对样本数；
- 纯人工和 AI 辅助的中位有效用时、差值和节省比例；
- 两种模式的准确率、百分点差值；
- “更快且更准”的学生人数和比例；
- 覆盖率、证据准确率、AI 采纳率、修改率、错误纠正率和错误采纳率；
- 按学生、论文、序列和数据质量状态筛选；
- 查看字段级答案、评分理由和异常计时记录；
- 导出 UTF-8 CSV。

“新建项目、添加论文、人工逐项打分”不再是默认实验的主流程。已有人工复核能力保留为可选覆盖；覆盖结果必须同时保留自动评分和人工评分来源，不能静默改写原始自动结果。

## 5. 数据口径

### 5.1 有效用时

客户端每 15 秒发送一次活动心跳。只有同时满足以下条件的时间片计入 `active_seconds`：

- 页面可见；
- 当前提交未锁定；
- 最近 120 秒内存在键盘、鼠标、触摸、滚动或答案编辑事件。

服务端把单次心跳增量限制在 20 秒以内，使用幂等事件 ID 防止重复累加。刷新、短时断网和重新登录不会清零。系统另外保留 `started_at`、`submitted_at` 和总墙钟耗时，以便检查长时间离开页面等异常。

看板的主要速度指标使用每种模式的学生级 `active_seconds` 中位数。节省比例为：

`(人工中位用时 - AI 辅助中位用时) / 人工中位用时`

若人工中位用时为 0 或有效样本为空，比例显示为不可计算，不显示误导性的 0%。

### 5.2 值准确率和覆盖率

每篇论文固定六个应答字段：Cation、Anion、Substrate、Temperature、Load、COF。

- 值准确率 = 正确字段数 / 6；空白计为错误。
- 值覆盖率 = 非空字段数 / 6。
- 模式总体准确率先计算每名学生在该模式下的准确率，再汇总中位数和均值；看板主卡使用中位数。

文本字段先执行 Unicode 规范化、大小写与空白归一化，再与标准答案或允许别名比较。数值字段转换为配置中的标准单位后，按字段配置的绝对或相对容差比较。评分结果保存字段级状态、规范化值、命中的规则和评分版本。

### 5.3 证据指标

- 证据覆盖率 = 同时填写页码和证据的字段数 / 6。
- 证据准确率 = 证据判定正确的字段数 / 6。

证据正确要求页码落在配置允许范围内，并满足相应关键词组规则。未填写证据计为不正确，同时通过证据覆盖率明确展示缺失原因。自动证据评分只使用确定性规则，不调用大模型。

### 5.4 AI 行为指标

所有 AI 指标均以 AI 辅助轮的字段为单位：

- 建议采纳率 = 最终规范化答案与 AI 初始答案一致的字段数 / AI 有建议字段数；
- 建议修改率 = 最终规范化答案与 AI 初始答案不同的字段数 / AI 有建议字段数；
- 错误纠正率 = AI 初始值错误且最终值正确的字段数 / AI 初始值错误字段数；
- 错误采纳率 = AI 初始值错误且最终仍与 AI 一致的字段数 / AI 初始值错误字段数。

分母为 0 时显示“—”，不显示 0%。AI 初始值始终按同一标准答案和评分版本重新评分，不能把教师历史评分直接当作基准。

### 5.5 配对比较和数据质量

主分析只包含两轮均提交且两轮有效用时均大于 0 的学生。未完成者、异常计时者和被人工标记排除者分别计数并显示原因，不从完成率中消失。

每名有效学生形成一组“AI 辅助 - 纯人工”差值。看板默认显示：

- 两种模式的中位数；
- 学生内中位差值；
- 绝对差与相对差；
- 有效配对样本数；
- 更快、更准、同时更快且更准的人数。

详细统计区提供配对 Wilcoxon 检验和学生级差值的 bootstrap 95% 置信区间，但不把单一 p 值作为主结论。看板同时按论文和序列显示结果，用于检查论文难度或先后顺序是否产生明显偏差。

## 6. 数据模型与兼容迁移

现有表继续保留。迁移使用显式 schema 版本和事务，启动时检查列/表是否存在，能够重复执行。

### 6.1 `teaching_projects` 新增信息

- `experiment_kind`：旧项目为 `legacy`，默认实验为 `crossover_v1`；
- `config_version`：默认配置版本；
- `config_checksum`：不可变快照校验和；
- `is_default`：是否为当前默认实验。

### 6.2 `teaching_papers` 新增信息

- `gold_snapshot_json`：标准值、页码和证据目标；
- `scoring_rules_json`：别名、单位、容差和关键词规则；
- `config_version`：题目所属配置版本。

### 6.3 `teaching_participants` 新增信息

- `sequence_code`：`manual_then_ai` 或 `ai_then_manual`；
- `completed_at`：两轮均完成的时间；
- `excluded_at`、`exclusion_reason`：可选的数据质量排除记录。

默认项目在业务层和数据库唯一索引层保证学生标识唯一。旧项目仍沿用原有“项目 + 组别 + 学生标识”规则。

### 6.4 `teaching_submissions` 新增信息

- `round_no`：1 或 2；
- `mode`：`manual` 或 `ai_assisted`；
- `active_seconds`：服务端累计有效时间；
- `ai_initial_json`：该轮不可变 AI 初始快照；
- `auto_value_scores_json`、`auto_evidence_scores_json`：自动评分结果；
- `scoring_version`：评分规则版本；
- `auto_scored_at`：自动评分时间。

现有 `(project_id, paper_id, participant_id)` 唯一约束允许同一学生针对两篇论文各有一条提交，适合两轮设计。旧提交新增列使用安全默认值，不参与新版配对分析。

### 6.5 新表 `teaching_activity_events`

保存提交级活动和审计事件：

- 稳定事件 ID；
- 提交 ID；
- 事件类型；
- 可选字段键；
- 客户端时间与服务端接收时间；
- 受限的活动秒数增量；
- 不含论文全文的精简 JSON 元数据。

事件 ID 在提交内唯一，保证重试幂等。常规键盘内容不进入事件表，避免保存不必要的逐键输入和隐私数据。

## 7. 模块边界

`lib/teaching.ts` 保留现有公开入口，并把新增职责拆到以下模块：

- `lib/teaching/config.ts`：读取、验证和初始化默认实验；
- `lib/teaching/assignment.ts`：身份恢复、平衡分组和两轮创建；
- `lib/teaching/scoring.ts`：值、单位、证据和 AI 行为评分；
- `lib/teaching/activity.ts`：心跳幂等、有效时间累计和异常判断；
- `lib/teaching/analytics.ts`：配对汇总、分层结果和导出数据；
- `lib/teaching/migrations.ts`：版本化 SQLite 迁移。

每个模块使用明确输入输出，不直接依赖 React 组件。数据库写入由服务层事务包裹，组件不拼装 SQL 或统计公式。

## 8. API 与页面状态

### 8.1 会话 API

学生登录请求只提交规范化前的学生标识。服务端初始化默认实验、恢复或创建参与者、生成学生会话并返回 `/teaching/student`。教师登录继续使用现有密码和角色会话。

### 8.2 学生 API

- `GET`：返回当前未完成轮次；两轮完成则返回完成状态。
- `PATCH`：按乐观版本号保存答案，保持现有冲突保护。
- `POST action=heartbeat`：幂等累计活动时间。
- `POST action=submit`：校验必填值、锁定当前轮、自动评分并返回下一轮或完成状态。

纯人工响应使用独立序列化器，结构上不可能包含 AI 或标准答案字段。AI 辅助响应只包含该轮 AI 初始建议，不包含标准答案和评分规则。

### 8.3 教师 API

教师看板 API 返回已聚合结果、数据质量标记和按需加载的学生明细。CSV 导出使用同一分析服务，避免页面数字与导出数字口径不一致。

## 9. 错误处理

- 默认配置无效：阻止新实验加入，教师看板显示具体缺失字段；
- 论文链接不可访问：学生页面提供 DOI 备用链接并记录来源错误；
- 草稿版本冲突：保留服务器版本，提示刷新恢复，不覆盖较新答案；
- 心跳重复或延迟：按事件 ID 去重并限制最大增量；
- 第一轮未提交：禁止访问或修改第二轮；
- 已提交轮次：所有答案和活动写入均返回锁定冲突；
- 自动评分失败：提交仍保持锁定，标记为 `scoring_error` 并允许后台安全重算；
- 统计样本不足：展示实际 N 和“样本不足”，不计算置信区间或显著性结论。

## 10. 隐私与研究透明度

- 学生使用学号或姓名缩写，不要求真实姓名；
- 导出默认包含学生标识，教师可选择匿名化导出；
- 学生开始前看到简短说明：会记录有效时间、答案修改和 AI 建议使用情况；
- 不记录逐键文本、剪贴板内容或论文全文；
- 所有看板结论标明样本量、排除数和评分版本；
- 系统表述为本班教学实验结果，不自动外推为普遍因果结论。

## 11. 测试策略

### 11.1 单元测试

- 30 个新身份得到精确的 15/15 序列分配；任意时刻人数差不超过 1；
- 相同身份重复加入保持原分组和两轮记录；
- 文本别名、Unicode、空白和大小写规范化；
- 温度、载荷和 COF 的单位换算与容差边界；
- 空白按错误计入准确率；
- 页码范围与证据关键词评分；
- AI 采纳、修改、纠正和错误采纳的分母为 0 行为；
- 心跳去重、20 秒上限、120 秒闲置和页面隐藏行为；
- 中位数、配对差值、完成/排除人数及置信区间。

### 11.2 服务与 API 测试

- 默认配置初始化幂等，配置漂移不会覆盖已开始实验；
- 加入和分组在并发请求下保持均衡；
- 纯人工工作区不泄露 AI 或标准答案；
- AI 辅助工作区只暴露 AI 初始建议；
- 第一轮锁定后正确进入第二轮；
- 乐观锁、重复提交和断线恢复；
- 自动评分失败可重算且不会解锁答案；
- 旧数据库迁移后原项目、提交和人工复核仍可读取。

### 11.3 组件与端到端测试

- 学生首次进入、两轮完成和重复登录恢复；
- 纯人工字段为空，AI 辅助字段预填且可编辑；
- 闲置提示和有效计时显示；
- 教师零配置打开看板，无空项目创建步骤；
- 看板卡片、筛选、异常提示和 CSV 数字一致；
- 30 名模拟学生数据下，速度、准确率和“更快且更准”结论正确。

## 12. 验收标准

1. 全新数据库访问 `/teaching` 后可直接加入默认实验，无需教师预配置。
2. 连续加入 30 个不同学生标识后，两条序列各 15 人。
3. 每名学生只能按分配顺序完成两轮，纯人工轮无法从响应或页面得到 AI/标准答案。
4. AI 辅助轮能预填建议，并正确记录未修改、修改、纠错和错误采纳。
5. 有效用时在页面隐藏或连续闲置 120 秒后不再增加，恢复操作后继续。
6. 提交后自动生成字段级可解释评分，不需要教师逐项判定。
7. 两轮完成后，教师看板自动出现配对速度和准确率结果、有效 N、排除数和核心 AI 行为指标。
8. 看板与 CSV 使用完全相同的统计口径。
9. 原有教学数据和人工复核记录在迁移后仍可访问。
10. 单元、API、组件和端到端验证全部通过。
