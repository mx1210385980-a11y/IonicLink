# 先看全链路，再看具体框架

RAG 常被讲成“向量检索 + 大模型”，但真正稳定的系统一般至少包含以下环节：

- 文档准备
- 分块策略
- 索引构建
- 检索召回
- 重排过滤
- 上下文拼接
- 生成回答
- 引用与评估

> [!WARNING]
> 如果你还没想清楚每一层在补偿什么误差，就急着比较框架和 embedding 模型，通常会花很多时间却看不到本质差异。

## 推荐的记录方式

1. 一篇讲整体链路
2. 一篇讲分块策略
3. 一篇讲召回与重排
4. 一篇讲评估方法
