# Pipeline

Pipeline 负责把“文献进入系统之后会发生什么”讲清楚。它关注的是流转、运行和状态，而不是知识解释或人工判定。

## 页面职责

- 承载文献上传和注册入口。
- 展示抽取运行、批处理队列和 Agent 执行过程。
- 暴露失败原因、重试动作和运行链路。

## 建议承载的内容

- 文献上传
- 文献注册与批处理
- 抽取运行状态
- Agent 执行过程
- 批量同步与导入
- 失败重跑与队列恢复

## 设计原则

Pipeline 强调的是“过程可见”。用户应该能从这里看清一篇文献从进入系统到变成可审阅结果，经历了哪些阶段、卡在了哪里、还能做什么。

## 和其他一级域的边界

- 如果内容是在判断抽取结果是否可信，它属于 Review。
- 如果内容是在整理沉淀后的可检索资产，它属于 Knowledge。
- 如果内容只是平台当前状态摘要，它应该退回 Home。
