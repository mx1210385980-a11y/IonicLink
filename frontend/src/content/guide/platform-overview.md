# 为什么把平台做成博客系统

这个系统不只是一个展示页面，而是一个长期维护的个人学习中枢。你可以把它看成三层结构：

- 左侧是知识结构，负责告诉你内容分成哪些栏目。
- 中间是阅读空间，负责承载正文、解释说明和经验总结。
- 右侧是内容目录与站点公告，负责帮助你快速定位当前文章。

> [!IMPORTANT]
> 后续维护时，优先把平台说明、模块解释、设计取舍写进 Markdown，而不是只留在聊天记录和临时备忘里。

## 推荐记录的内容

- 平台模块介绍，例如上传、解析、检索、实验、部署。
- AI 相关学习，例如提示词设计、数据清洗、模型评估、RAG。
- 项目迭代日志，例如为什么改版、踩了哪些坑、哪些思路被证伪。

## 为什么选 Markdown

Markdown 的优点不是“轻量”，而是稳定。

- 它适合长期维护，文本文件不会被界面工具绑死。
- 它天然适合版本管理，任何改动都可以被追踪。
- 它可以被自动读取、索引、渲染，因此最适合做知识库底层格式。

## 这套页面现在已经具备什么

- 按目录自动加载 `src/content` 下的文章。
- 自动生成左侧栏目树和右侧文章目录。
- 支持 Frontmatter 元数据，例如标题、摘要、日期、标签和排序。
- 支持基础 Markdown 语法，包括标题、列表、引用、提示框和代码块。
